# Routing and machine-oriented refinement
Route by requested outcome and observed failure, not incidental keywords.
- Review only: inspect and report; do not publish.
- Ordinary evolution: modify authorised reusable execution rules in an isolated candidate.
- Meta-evolution: candidate generation, allocation, or selection policy changes require comparisons across multiple prior cases.
- One-off answer: use the normal task workflow, optionally retain a durable observation.
- Domain-specific task: use the existing specialised capability for execution; use evolution only for a demonstrated reusable defect in it.
- Security/adversarial branch: apply when the request is adversarial evaluation, hostile retrieved instructions are present, or a documented threat surface affects the target. Use bounded probes, never convert ordinary stakes into threats, penalties, or invented urgency.

For machine-oriented prompt refinement preserve intent as a mapping:
source clause -> input/condition -> action -> output -> acceptance check.
Keep protected clauses separate from mutable implementation. Convert vague advice to testable behaviour only where evidence supports it; otherwise preserve uncertainty. Positive-first wording should say what to do and when; negative rules remain for exact forbidden actions, not rhetorical intimidation.

Resolve ambiguity proportionately. Read available sources, record reversible assumptions, and continue independent work. Ask only when materially different interpretations change the authorised target, correctness, external consequences, or acceptance criteria. Preserve unresolved conflicting source instructions visibly. Do not promote guesses to facts.

Long context: search external artifacts, load only relevant spans, retain anchors and completed results. Delegate only with available authorised tools and disjoint scope. Fresh contexts reduce contamination but do not prove independence. Count delegated work against the shared budget.
