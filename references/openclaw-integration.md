# OpenClaw integration
Use the currently exposed Skill Workshop tool for skill create/update/review/publication. Inspect its current mode: draft-oriented tools stage proposals; publication-only personal operations publish when requested. Do not invent tool flags or bypass this with extraction scripts.
Creating a replacement does not remove originals, activate a duplicate, enable hooks or schedule work. Those are distinct operations.

Choose one canonical skill for the evolution role when activating. Keep uncertainty-reduction and operational-loop skills as conditional supporting disciplines, not three competing orchestrators.

The optional bootstrap adapter preserves the source event shape (agent/bootstrap and context.bootstrapFiles). Test it locally; confirm the installed runtime actually supplies that shape before enabling. A local adapter test does not prove live compatibility.

State migration is explicit: retain old reports read-only, map meaningful fields to assets/template.json, label missing evidence not_run, and validate the new report. Do not reinterpret an old "VALID" result as evidence of behavioural improvement.
Promotion of durable facts into memory or instructions remains subject to current host rules and task authority. Share only necessary redacted evidence with authorised agents. Use available native delegation mechanisms rather than hard-coded session APIs.
